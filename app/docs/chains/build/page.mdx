# Build Your Own Blockchain

A complete mental model for building blockchains — what's different from building a web app or deploying Ethereum contracts, what you actually need to install, how the code is structured, and where it all runs.

---

## The Mental Model

Before anything else, understand what you're actually building.

### Compared to a Next.js app

| | Next.js App | Blockchain Node |
|--|-------------|----------------|
| What it is | Web server that handles HTTP requests | Peer process that syncs state with other nodes |
| State lives in | Database (Postgres, etc.) | Replicated across all nodes in the network |
| "Deploy" means | Push code to Vercel | Run a binary on a VPS that joins/creates a network |
| Trust model | You trust the server | No single server — consensus between nodes |
| Users interact via | Browser → HTTP → your API | Wallet → signed transaction → mempool → block |
| Scaling | Add servers behind a load balancer | Add validator/full nodes |
| Updates | Redeploy to Vercel | Coordinate upgrade across all node operators |

### Compared to deploying on Ethereum

| | Deploy on Ethereum | Build Your Own Chain |
|--|-------------------|---------------------|
| What you control | Your smart contract logic | Everything — consensus, block time, gas, tokenomics |
| Gas fees | Paid in ETH to validators | You define the fee structure |
| Security | Ethereum's validator set | Your own validator set |
| Effort | Medium (Solidity + deploy script) | Very High (full node software) |
| Time to launch | Hours | Weeks to months |
| When to do it | 90% of cases | App-chain, custom runtime, enterprise chain |

## How a Blockchain Actually Works

<Mermaid chart={`
flowchart TD
    U([User / Wallet]) -->|Signs transaction| M[Mempool]
    M -->|Picks pending txs| V[Validator / Sequencer]
    V -->|Bundles into block| B[New Block]
    B -->|Broadcasts to| N1[Node 1]
    B -->|Broadcasts to| N2[Node 2]
    B -->|Broadcasts to| N3[Node 3]
    N1 & N2 & N3 -->|Verify + add to chain| S[Chain State]
    S -->|Updated balances / contract state| U
`} />

Every node runs the same software and independently verifies every block. There is no central server. The "database" is the chain itself, replicated across all nodes.

## The Three Layers of Every Blockchain

<Mermaid chart={`
flowchart LR
    subgraph Application Layer
        SC[Smart Contracts / Runtime Logic]
    end
    subgraph Consensus Layer
        CON[Validator Selection\nBlock Proposal\nFinality]
    end
    subgraph Network Layer
        P2P[Peer Discovery\nGossip Protocol\nBlock Propagation]
    end
    Application Layer --> Consensus Layer --> Network Layer
`} />

| Layer | What It Does | In Ethereum | In Substrate |
|-------|-------------|-------------|--------------|
| Network | Find peers, share blocks/txs | devp2p | libp2p |
| Consensus | Agree on which block is valid | Gasper (PoS) | BABE + GRANDPA |
| Application | Execute transactions, update state | EVM | FRAME Pallets |

When you "build a blockchain" you're implementing all three layers — or using a framework that gives you 2 of them pre-built.

## Framework Comparison

<Mermaid chart={`
flowchart TD
    Q{What do you need?}
    Q -->|Learn internals| PY[Python from scratch]
    Q -->|Max performance + control| RS[Rust from scratch]
    Q -->|Polkadot ecosystem + custom runtime| SUB[Substrate]
    Q -->|Sovereign L1 + IBC cross-chain| COS[Cosmos SDK]
    Q -->|EVM L3 on Arbitrum| ORB[Arbitrum Orbit]
    Q -->|EVM L2 on Ethereum / Superchain| OPS[OP Stack]
    Q -->|Enterprise permissioned| HYP[Hyperledger Fabric]
    Q -->|Private Ethereum-based chain| QUO[GoQuorum]
`} />

| Framework | Language | You Build | Framework Gives You | Deploy Target |
|-----------|----------|-----------|---------------------|---------------|
| Python scratch | Python | Everything | Nothing | Your VPS |
| Rust scratch | Rust | Everything | Nothing | Your VPS |
| Substrate | Rust | Pallets (business logic) | Network + consensus + runtime | Your VPS or Polkadot relay |
| Cosmos SDK | Go | Modules (business logic) | Network + consensus (Tendermint) | Your VPS |
| Arbitrum Orbit | Solidity + Go config | Chain config + bridge contracts | Full rollup stack (Nitro) | Arbitrum One / Nova |
| OP Stack | Solidity + Go config | Chain config + L1 contracts | Full rollup stack | Ethereum L1 |
| Hyperledger Fabric | Go or Node.js | Chaincode (smart contracts) | Network + ordering + MSP | Your VPS / cloud |
| GoQuorum | Go + Solidity | Smart contracts + network config | Modified Geth + Tessera | Your VPS |

## Dependencies to Install

### Python (from scratch)

```bash
pip install flask cryptography requests ecdsa
```

No special toolchain. Just Python 3.10+.

### Rust (from scratch or Substrate)

```bash
# Install Rust
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
source $HOME/.cargo/env

# For Substrate — add WASM target
rustup target add wasm32-unknown-unknown
rustup component add rust-src

# Substrate node template
git clone https://github.com/substrate-developer-hub/substrate-node-template
cd substrate-node-template
cargo build --release   # takes 15-30 min first time
```

### Cosmos SDK (Go)

```bash
# Install Go 1.21+
brew install go   # macOS
# or: https://go.dev/dl/

# Install Ignite CLI (scaffold tool)
curl https://get.ignite.com/cli | bash

# Scaffold a new chain
ignite scaffold chain mychain
cd mychain
ignite chain serve
```

### Arbitrum Orbit

```bash
# Node.js 18+ required
node --version

# Clone the orbit setup scripts
git clone https://github.com/OffchainLabs/orbit-setup-script
cd orbit-setup-script
npm install

# Docker for running the nitro node
brew install --cask docker
```

### OP Stack

```bash
# Foundry (for contracts)
curl -L https://foundry.paradigm.xyz | bash && foundryup

# Go 1.21+ (for op-node and op-geth)
brew install go

# Clone the monorepo
git clone https://github.com/ethereum-optimism/optimism
cd optimism
pnpm install
make op-node op-geth
```

### Hyperledger Fabric

```bash
# Docker + Docker Compose required
brew install --cask docker

# Download Fabric binaries + Docker images
curl -sSL https://bit.ly/2ysbOFE | bash -s -- 2.5.0 1.5.0
# Downloads: peer, orderer, configtxgen, cryptogen, fabric-ca-client

# Node.js for chaincode (optional)
node --version  # 18+
```

## Environment Variables

### Substrate / Cosmos / Rust scratch

Minimal — mostly CLI flags, not env vars. Key config files instead:

```bash
# Substrate: chain_spec.rs defines genesis
# Runtime behavior configured via pallets in code

# Cosmos: config/config.toml + config/app.toml
[rpc]
laddr = "tcp://0.0.0.0:26657"

[p2p]
laddr = "tcp://0.0.0.0:26656"
seeds = "node1_id@node1_ip:26656,node2_id@node2_ip:26656"
```

### Arbitrum Orbit

```bash
# .env
PARENT_CHAIN_RPC="https://arb-sepolia.g.alchemy.com/v2/YOUR_KEY"
DEPLOYER_PRIVATE_KEY="0xYOUR_DEPLOYER_KEY"
CHAIN_OWNER_ADDRESS="0xYOUR_OWNER_ADDRESS"
CHAIN_ID=412346
```

### OP Stack

```bash
# .envrc
export L1_RPC_URL="https://eth-sepolia.g.alchemy.com/v2/YOUR_KEY"
export L1_RPC_KIND="alchemy"
export GS_ADMIN_PRIVATE_KEY="0x..."
export GS_BATCHER_PRIVATE_KEY="0x..."
export GS_PROPOSER_PRIVATE_KEY="0x..."
export GS_SEQUENCER_PRIVATE_KEY="0x..."
export L1_CHAIN_ID=11155111
export L2_CHAIN_ID=42069
```

OP Stack needs 4 separate wallets (admin, batcher, proposer, sequencer) — each funded with testnet ETH.

### Hyperledger Fabric

No `.env` file — config is in YAML files:

```yaml
# config/configtx.yaml (key fields)
Organizations:
  - Name: Org1MSP
    ID: Org1MSP
    MSPDir: organizations/peerOrganizations/org1/msp
    Policies:
      Readers: { Type: Signature, Rule: "OR('Org1MSP.member')" }
      Writers: { Type: Signature, Rule: "OR('Org1MSP.member')" }
      Admins:  { Type: Signature, Rule: "OR('Org1MSP.admin')" }
```

## Folder Structures

### Substrate

```
my-chain/
  node/src/
    main.rs           # Binary entrypoint
    service.rs        # Node services (network, RPC, consensus)
    chain_spec.rs     # Genesis config
  runtime/src/
    lib.rs            # construct_runtime! — wires all pallets
  pallets/
    my-pallet/src/
      lib.rs          # Your business logic (#[pallet::*] macros)
  Cargo.toml
```

### Cosmos SDK

```
my-chain/
  app/
    app.go            # Module wiring
  cmd/mychaind/
    main.go           # CLI entry
  x/mymodule/         # Custom module (like a pallet)
    keeper/
      keeper.go       # State read/write
      msg_server.go   # Tx handlers
    types/
      msgs.go
    module.go
  proto/              # Protobuf message definitions
  config/
    app.toml
    config.toml
```

### Arbitrum Orbit

```
orbit-chain/
  contracts/          # Solidity — deployed on parent chain
    scripts/
      deployOrbit.ts
    hardhat.config.ts
  nitro-node/
    nodeConfig.json   # Your chain config
    docker-compose.yml
```

### OP Stack

```
op-chain/
  packages/contracts-bedrock/
    deploy-config/
      my-chain.json   # L2 chain config
    scripts/
      Deploy.s.sol    # Foundry deploy
  op-node/
    rollup.json       # Rollup config
  op-geth/
    genesis.json      # L2 genesis
```

### Hyperledger Fabric


## Where Does It Run?

This is the biggest difference from Vercel-hosted Next.js apps.

| | Next.js on Vercel | Blockchain Node |
|--|-------------------|----------------|
| Hosting | Vercel manages everything | You manage VPS(es) |
| Uptime | Vercel's SLA | Your responsibility |
| Scaling | Automatic | Add more nodes manually |
| Cost | Free tier available | $5–50/mo per node on VPS |
| Access | HTTPS via domain | TCP ports (P2P + RPC) |

### Minimum VPS per node type

| Node Type | RAM | vCPU | Storage | Why |
|-----------|-----|------|---------|-----|
| Substrate validator | 4 GB | 2 | 80 GB | WASM runtime execution |
| Cosmos validator | 4 GB | 2 | 100 GB | State + Tendermint consensus |
| Orbit sequencer | 8 GB | 4 | 200 GB | L2 execution + L1 posting |
| OP Stack sequencer | 8 GB | 4 | 200 GB | op-geth + op-node |
| Fabric peer | 2 GB | 2 | 50 GB | Per-org peer node |

You typically need **at least 3 validator nodes** on separate machines for real Byzantine fault tolerance. One node = centralized = not a real blockchain.

### Ports to open

| Protocol | Port | Used By |
|----------|------|---------|
| P2P / gossip | 30303 (Geth), 26656 (Cosmos) | Node-to-node communication |
| RPC (HTTP) | 8545 (EVM), 26657 (Cosmos) | Wallets, dApps connecting to your chain |
| WebSocket | 8546 | Real-time subscriptions |
| Substrate P2P | 30333 | Substrate nodes |
| Substrate RPC | 9944 | Polkadot.js, frontends |

```bash
# Open ports on Ubuntu VPS
ufw allow 30303/tcp   # P2P
ufw allow 8545/tcp    # RPC (restrict to trusted IPs in prod)
ufw allow 8546/tcp    # WS
ufw enable
```
